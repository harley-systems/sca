The appliance verify command checks that the platform is set up as an
air-gapped CA appliance, and prints one row per check, ok, FAIL, n/a or
skipped:

  boot      - the platform profile's own check, e.g. U-Boot booting from SPI;
              n/a on a platform that boots USB natively (boot_prep=none)
  root      - the root file system is on a USB disk
  rtc       - rtc0 is the battery-backed clock, and the kernel sets the time
              from it at boot (hctosys=1)
  clock     - the time is not synchronised from the network by NTP
  hwclock   - fake-hwclock, which can walk the clock backwards at boot, is
              masked
  power cut - the time the kernel read from rtc0 at boot is not earlier than
              the end of the previous boot; skipped while the journal holds no
              previous boot

A skipped check is one that applies but could not run this time: it is neither
a failure nor a pass. The power cut check needs the journal to remember the
previous boot, which takes journald with Storage=persistent (a /var/log/journal
directory alone is not enough) and a /var/log that is not on a zram disk; the
row names whichever of the two is missing. Run verify again after a power cut.

Every check runs, even after one fails. The exit status is non-zero if any
check fails, so verify can be used from a script. The power cut check reads the
kernel log: run verify with sudo, or as a member of the systemd-journal group.

The platform is detected from the device tree or, on a platform without one
(x86), from the machine's architecture; --platform names it instead. A profile
that is a proposal, not verified on hardware, is reported as such first.
